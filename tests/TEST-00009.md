## Evidence per GW

### GW1 — Valid token → SSE final with CLI-equivalent answer
- `TestChatAuthOK` (`internal/server/server_test.go`): 200 + `text/event-stream`; first event `start`, last event `final` with `text == "the answer"`.
- Final text originates from the `Handler` seam → same agent output the CLI would emit (ties to GW7).

### GW2 — 401 on missing/invalid token
- `TestChatUnauthorized`: returns 401; no SSE frame in body.
- **Live** `/v1/chat` with no `Authorization` header → HTTP 401.

### GW3 — 400/422 validation, no SSE
- `TestChatBadRequest`: `{not-json` → 400, no SSE.
- `TestChatEmptyPrompt`: `{"prompt":"   "}` → 422, no SSE.
- **Live** confirmation of both statuses.

### GW4 — tool `stream` before `final`
- `TestChatStreamsToolThenFinal` (HTTP layer maps events → `stream` frames in order).
- `TestRun_emitsToolEventsThenFinal` (`internal/agent/event_test.go`): agent `OnEvent` emits
  `start, tool(start), tool(result), ..., final`.

### GW5 — disconnect cancels handler; MCP child closed (no orphan)
- `TestChatClientDisconnectCancelsHandlerAndStreamsCancelled`: client cancels request ctx →
  handler ctx observed `Canceled` (polled for async propagation).
- The real `Runner.Chat` ensures `defer client.Close()` on every path, so cancellation closes the
  MCP child; child termination is proven by `TestStdioServer_Close_LeavesNoOrphan`
  (`internal/mcpclient`, exit-marker within 3s).

### GW6 — process survives post-`start` error
- `TestChatSurvivesAfterStreamedError`: req1 → handler error → `event:error`; req2 on the **same**
  live server → 200 `event:final` with recovered answer. MCP typed failures
  (`ErrTimeout`/`ErrInvalidResponse`) covered in the `internal/mcpclient` suite.

### GW7 — CLI unchanged
- `go test ./... -count=1` green across all 10 packages after the additive observer seam;
  `cmd/server` behavior and bootstrap untouched.

### GW8 — HTTP layer SDK-free
- `internal/server` test files import stdlib only (no `mcp-go`, no `genai`); verified by source grep.

### GW9 — concurrent independent lifecycles
- `TestChatConcurrentRequestsIndependentLifecycle`: 4 concurrent requests, all reach `final`;
  `maxActive ≥ 2` proves in-flight overlap isolation.
